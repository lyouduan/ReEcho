# ReEcho 策划 AI 经验库

本目录保存按策划稳定身份拆分的可复用操作经验。策划工作规则以 `shared/DESIGNER_RULES.md` 为唯一权威；本文件只定义经验文件的命名和条目格式，不重复分支或权限规则。

## 使用方式

- 文件名为 `<策划身份>.md`，身份必须与策划协作分支和 `issues/<策划身份>/` 中的身份完全一致。
- 策划 AI 每次接入先读取自己的经验文件；第一次实际修改时创建该文件。
- 每次实际修改都追加一条，成功和失败都记录。相同结论可引用旧条目并补充新证据，不复制整段内容。
- 经验的首要目标是回答：**在哪里改什么可以使什么生效**。必须让下一位 AI 能据此找到权威入口、执行刷新并复现结果。
- 只记录有实际验证或失败观察支持的事实；不得写入凭据、私密机器路径、完整大日志或未经验证的推测。

## 身份文件模板

```markdown
# <策划身份> 的 ReEcho 策划经验

## YYYY-MM-DD HH:MM - <简短主题>

- 结果：成功 / 未生效 / 效果错误 / 需要程序
- 事项与分支：事项标识；对应 `issue/<策划身份>/<简述>`、`request/<策划身份>/<简述>` 或 `merge/<策划身份>/<简述>`；提交号（尚未提交时写“待提交”）
- 目标：策划希望看到的变化
- 生效映射：在 `<文件/Sheet/资产>` 修改 `<字段/对象/值>`，会使 `<界面/玩法/数值/资源效果>` 生效
- 修改：准确路径、Sheet/Table/稳定 ID、字段、旧值和新值
- 刷新方式：运行的脚本、参数，或关闭并重新打开 `ReEcho.uproject` 的步骤
- 验证入口：关卡、界面、操作步骤、校验命令和相关日志摘要
- 策划确认：确认人给出的结论，以及是否明确同意推送
- 限制与踩坑：前置条件、不会影响的范围、不生效症状和已排除原因
- 报告交接：无，或 `issues/<策划身份>/bugs/...md`、`issues/<策划身份>/requests/...md`
```

条目应短而具体。不要只写“改了表格后生效”，应写清准确入口，例如“在某工作簿的某 Sheet 修改某稳定 ID 的某字段，运行哪个同步脚本并重启项目后，哪个界面的哪个数值发生变化”。
